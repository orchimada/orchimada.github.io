03Other abstractions → physical

The instrument's vocabulary.

Lit dots were the first idea. Teenage Engineering suggests a whole parts bin — each part turns an abstract thing into something you can read or operate. These are the components the system is built from. Click the live ones.

Dot grille

signal from ground — the field is always there; meaning is the dots that light.

20M

Segment display

the one value — a single number that matters, glowing like a readout.

Button + LED

discrete state — on or off, with a light that tells the truth. Filters, nav.

Knob

continuous control — figure↔ground, focus, intensity. Turn it.

Fader

magnitude — a level you set and see. Effort, scope, priority.

Patch jack

connection — labeled in/out points; sections route signal to each other.

VU meter

live magnitude — impact as bouncing bars. Metrics that breathe.

Mode switch

the two languages — temperature you flip. The whole machine changes job.

04Where to push

Decisions before I build tokens.

  1. Does the instrument metaphor go all the way, or stay a motif? Full-device (every page is a panel with jacks + a mode switch), or device-language used as accents on otherwise clean pages?
  2. Which vocabulary parts make the cut? Dot grille + segment + mode switch are core. Knob, fader, VU, patch jack — keep all, or only where they carry real meaning?
  3. Accent: signal red stays the one paint — or pull toward TE orange (#ff5b22)?
  4. Then I build the token kit + the two real pages — business self-page (SELL) and engineering skill-page (EXPLAIN) — proving the switch on live content.
